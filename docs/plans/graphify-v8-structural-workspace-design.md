### Source observation must cover what extraction actually consumes

The recommended v8 adapter uses the scoped I/O context directly for source reads, rather than retaining W's code-only snapshot as a false completeness boundary. It preserves W's descriptor pinning and repeated observations, but redirects v8's existing input operations to that authority. There is no pathname monkeypatch, second parser, or full-repository blind copy. Reads return bytes from no-follow pinned descriptors; probes and listings record present/absent entries and rooted directory identity. Repeated reads of an input in one build must match the first bytes/identity or fail. An operation outside the registered source/policy/Git allowlist, or a built-in path not adapted to this context, must refuse this workspace build rather than fall back to unrestricted `Path` I/O. Ordinary calls without the context retain their existing behavior.

Persist a bounded, canonical **source-input manifest** beside `graph.json` within the sealed payload: admitted-file identities/hashes, effective policy and Git routing/ref observations, supporting-file reads, negative probes and consulted directory memberships. Use source-relative labels and explicit bounded Git/policy labels, never scratch paths. Directory evidence excludes atime and unrelated operational output; content/type/mode and stable bindings remain material. This manifest is evidence, not authority to read arbitrary paths: validate its schema, counts/bytes and root allowlist before any reopen. A present external dependency not inside the supported allowlist is an explicit unsupported-source result, not silent absence.

Proposed adapter contract **2** adds an optional validated `input_manifest` to `observe`; `StructuralBuild` returns the corresponding manifest identity and complete per-code-input dispositions. The lifecycle first freezes ordinary source/policy authority, builds with the scoped reader, then takes two complete agreeing observations covering both detection and the final consumed-input manifest, checks every build read against them, and binds that result into completion/certification. Query uses the receipt-verified manifest to repeat that same inventory and input observation without re-running extraction. The detector ID and ABI name this new interpretation. Added/deleted admitted files are still found by complete detection; negative probes/listings prevent an optional metadata file appearing unnoticed. A build may not redefine a frozen request's source observation on retry: freeze its final observed input digest as an explicit staged-completion binding, distinct from the request's initial detection digest, and require both to agree on shared inputs. This binding requires an explicit versioned staged-record change; it is not a silent reinterpretation of W state v1.

This is the principal implementation cost. The first slice must establish the scoped engine I/O contract and account for the built-in reader paths using representative resolver fixtures before lifecycle wiring. Include capital-F Fortran's external `cpp` preprocessing (`V extractors/fortran.py:11–46`): it must use bounded recorded inputs or explicitly refuse the workspace path; a child process cannot bypass the read context. An uncovered reader is a failed slice, not permission to certify a smaller corpus. Source freshness remains **observed-current**, not an atomic snapshot or proof against changes made and reverted between observations.

**Memory-only query tokenizer.** The pinned optional jieba 0.42.1 implementation reads an ambient temporary cache or creates/replaces one on first initialization (inspected installed `jieba/__init__.py:115–154`). Add an engine-owned optional segmenter parameter through query-term construction into `_query_graph_text`. For certified calls with the Chinese extra installed, create a private tokenizer initialized from the same installed dictionary entirely in memory (the pinned `get_dict_file`/`gen_pfdict` path and initialized-instance state), then reuse its unchanged tokenization/HMM logic. Do not call its disk-cache initializer, read ambient caches, mutate the global tokenizer, or silently fall back to different segmentation. Without the extra, preserve v8's existing bigram behavior. Failure to establish the qualified memory-only path with the extra present withholds the query. Ordinary queries retain their default tokenizer behavior. S1/S4 must qualify the pinned API and cold-process token/ranking parity; A8 intercepts filesystem writes across all locations, including temp/home, with absent and misleading caches. Candidate query launch must also suppress Python bytecode writes before loading candidate modules; installed-entry-point fixtures must verify this rather than testing only an already-imported function.

**Two protocols, no nested commit.** V's `transaction.py` owns ordinary project `graphify-out` capabilities, receipts, watch intent, prepared transfers and repair. Its term “prepared workspace” is a transaction scratch area, not the external certified workspace. W's lifecycle owns certified generations. The adapter uses engine computation/serialization below the ordinary publication layer; it never opens a project transaction in generation staging. Thus there is no ordinary output receipt to reinterpret as workspace certification, no dual lease owner, and no cross-protocol recovery replay. Existing project outputs can continue independently and are excluded from workspace source authority.

**Enforced immutable boundary.** Add a small engine-side ordinary-output admission guard, independent of macOS workspace imports, used before output creation, transaction locks/recovery, export/cache/log writes and their direct library entry points. The new workspace state root has a durable versioned ownership sentinel installed before any descendant staging is allocated. Descriptor-walk output ancestry; a workspace sentinel reserves the entire tree (staging, generations and quarantine) against ordinary writes, even with `--force`, `create=True`, changed environment or missing/corrupt generation receipts. Malformed ownership evidence fails closed. Validate bindings again before mutation, including parent replacement races. This sentinel confers only **denial**, never workspace write authority; only the workspace descriptor writer can act under its existing fence. Ordinary recovery must refuse the tree without adding even its own lock/receipt. The added state-root marker and staged/input-manifest records are included in the new state-format contract and package proof. Copies detached from managed state lose certified authority; this does not claim protection against a hostile same-user process rewriting both payload and authority.

Historical W trees lack that new sentinel. New code must also recognize the retained W generation/receipt/coordination layout conservatively for write refusal, using existing-only descriptor inspection; it must not install markers or repair old state merely to inspect it. This defensive refusal is independent of whether D3 grants old-state query support. Unknown managed formats remain reserved/fail-closed. The guard cannot depend only on the current XDG root or package version.

### Crash/retry and maintenance safety

- Reuse W's exact-request recovery, not “start again”: same generation/request/attempt authority is checked; a different nonterminal request blocks. Successor fencing cannot adopt another reservation or broaden the frozen tuple. Before retrying, inspect durable effects.
- Unfinished unsealed staging may be reset only by its exact fenced recovery after intent is durable. COMPLETE adopts the exact sealed inventory. A receipt rename before CERTIFIED requires full receipt/payload/journal verification and completion of that already-authorized boundary; it does not rerun the engine against a newer source. PROMOTED replay returns the same verified result after release. No success receipt before leases/heartbeats are released.
- Canonically established source/active-source/pointer/migration/compatibility drift permits the existing intent-first terminal abandonment of that request. Source unavailability alone is not proof of drift. Stale/incompatible running code cannot continue extraction or promote; bounded frozen-boundary recovery needs exact compatible evidence, otherwise refuse and retain recovery evidence.
- Short writes, EINTR, ENOSPC/EDQUOT/EIO, fsync/rename uncertainty and lease-renewal failure preserve a recoverable barrier. A pointer made visible without its required journal acknowledgement remains unreadable; an acknowledged visible pointer with residual intent may be queried under W's verified-reader exception, while mutation remains blocked.
- Keep rollback/repair/GC safety in the stores now: exact compatible last_good only; repair chooses verified evidence with a revision above all observed history; no arbitrary historical pointer selection. GC requires explicit capacity/protection sets, current/last_good, reservations/staging/recovery reachability and existing shared query locks. Retain coordination-lock identities. Intent-first quarantine and separate explicit purge remain; no startup cleanup, online GC or power-loss guarantee. Unknown semantic/decision reachability blocks GC. Public maintenance transports can follow later, but required internal pointer/journal/staged recovery cannot.

## Candidate, ABI and support contract

Propose a new whole-artifact tuple, **not** a relabelled W generation: distribution `graphifyy`; v8-line candidate version chosen at artifact freeze (no return to `0.9.16+workspace.1`); build `git:<exact-candidate-commit>`; engine baseline rooted at V and the resulting candidate commit; extractor/cache ABI `graphify-v8-structural-1`; adapter contract `2`; detector `graphify-v8/workspace-observer-v2`; new workspace state schema `2` for the changed staged observation and state-root ownership contract. Carry an explicit graph/input-manifest payload format version. Runtime-manifest envelope can remain v1 if its unchanged strict structure contains the new compatibility document; command request/result and status versions change only where their shapes/meaning change. Acceptance must decide that mechanically through schema fixtures, not a global version bump.

Do not use a wildcard “all v8” or version-only comparison. Manifest validators, selectors, fixtures, distribution metadata and runtime loader agree on one exact tuple and installed package identity. PROBE is explicitly non-executable/non-promoting. Frozen requests never upgrade themselves. Exact candidate hashes cover wheel, lock/export, all generated skill members, schemas/contracts, fixtures, provenance/SBOM, runtime authority and isolated compensation artifacts. Preserve the acyclic order: compatibility document → runtime manifest embeds it → outer trusted manifest covers both. Local trusted-manifest replacement by the same attacker is outside the tamper claim.

Installed authority remains one owned singular regular 0600 file under owned private 0700 external state, canonical bounded JSON, no duplicate keys or defaults (W `composition.py:161–197`, compatibility contract). Candidate proof installs only beneath disposable absolute HOME/XDG_STATE_HOME/CODEX_HOME. Explicit proof queue limits `8/16384/1` are not operational defaults. Required capacity/queue policy remains explicit; missing authority fails before state creation. Compensation restores candidate binary/authority/skill fixture bytes and preserves all generation bytes. Real upgrade/cutover, old-runtime quiescence and live mixed-process fencing are later adoption work, not implied by an isolated proof.

Preserve ordinary distribution/import/scripts (`graphifyy`, `graphify`, `graphify` and `graphify-mcp`), final CPython `>=3.14.2,==3.14.*`, existing platform behavior, v8 interpreter/hook/pointer safety and generated-skill ownership. Lazy workspace CLI dispatch must not import fcntl/macOS persistence on ordinary import/help/install/query paths. Workspace lifecycle is still non-elevated single-user macOS/local APFS with supported descriptor/durability primitives; no Linux/Windows workspace expansion. Diagnostic inspection must either use its supported existing-only primitives or return a stable unsupported result without writes. Preserve v8's existing Windows transaction mutation refusal; do not claim v8 currently mutates on every platform.

Keep language, database, media, MCP/HTTP and Leiden extras optional. Selected missing parser errors remain explicit. No unconditional native Leiden or semantic/classifier imports for registration/status. Generate skill changes from owners in `tools/skillgen`, keeping host round trips and ordinary launch safety; no hand-edited generated copies. Structural work has no identified dependency upgrade prerequisite yet. If artifact tooling demonstrates an actual setuptools/export incompatibility, repair that bounded build requirement against v8's lock rather than transplanting W's dependencies or CI enforcement.

## D3: old certified state is an unresolved release choice

No existing-state inventory was performed; old state may exist. Neither option is approved here.
